# 产品操作指南(零基础版)

> 给产品同学看的。不用懂任何代码,每步都告诉你三件事:**怎么做、在哪做、会有什么结果**。

## 你从头到尾只做三件事

```
① 建期次 ──► ② 投料 ──► ③ 跑流水线
```

剩下的——转文字、写成文、切单元、查风险、画图、冻结——全部自动完成。

## 第 1 步:建期次

**怎么做**:对你的 AI 助手说一句话:

> "创建期次 Q3,目标上线会议室预订"

(也可以敲:`specprot iteration create -n 期次-Q3 -p web,backend`)

**在哪做**:AI 编程工具的对话框,或终端。

**会有什么结果**:一个叫 `期次-Q3` 的文件夹,里面什么都准备好了:

```
期次-Q3/
├── 00-素材/          ← 你投料的地方(重点!)
├── web/              ← web 端需求文档的家
├── backend/          ← 后端需求文档的家
├── _shared/          ← 跨端共用
└── 04-交付/          ← 最后交出去的东西(先不用管)
```

## 第 2 步:投料

**怎么做**:把材料**拖进文件夹**——讨论记录、会议截图、Word/PDF、录音,统统可以:

```
期次-Q3/00-素材/
├── web/      ← 前端相关的扔这里
├── backend/  ← 后端相关的扔这里
└── shared/   ← 两边都有关的(业务规则、字段定义)扔这里
```

**在哪做**:文件管理器(访达 / 资源管理器)。

**会有什么结果**:什么都不用管,流水线会自动把它们转成文字、给图片建索引。

## 第 3 步:跑流水线

**怎么做**:对 AI 助手说:

> "跑流水线,交互模式"

**在哪做**:AI 编程工具的对话框。

**会有什么结果**:六步自动接力,每步产出都看得见:

| 步骤 | 产出 | 你会在哪看到 |
| :--- | :--- | :--- |
| ① 转换 | 素材变文字 | `00-素材/converted/` |
| ② 分析 | **完整需求文档**(七段:背景/场景/功能/页面接口/字段/规则/验收) | `web/REQUIREMENT.md` |
| ③ 切分 | 功能单元(预订、支付…) | `web/features/` |
| ④ 深化 | 风险清单 + 待确认清单 | 单元目录里的 RISK.md |
| ⑤ 收养 | 需求进入"正典库" | `.speccore/GLOBAL/` |
| ⑥ 冻结 | 交付包成形 | `04-交付/` |

**中途会停下来问你六件事**(这是刻意设计,替你把关):

1. 范围对不对?
2. 素材是不是空的?
3. 需求骨架填满没有?
4. 待确认的问题解决没有?
5. 风险裁决完没有?
6. 确认收养这些需求吗?

答完继续跑;答不上来的,说明需求还没想清楚——正好趁机想清楚。

## 第 4 步:随时体检(可选但推荐)

**怎么做**:写完一段需求后,随时说:

> "检查一下:用户支付订单,金额从余额扣除"

**在哪做**:AI 编程工具的对话框。

**会有什么结果**:一份体检报告,直接告诉你:

```
🩺 需求体检报告
① 骨架完整性   ⚠️ 缺:页面/接口、业务规则、验收标准
② 质量六维     ⚠️ 口语化"大概" / 无验收标准
③ 图资产建议   💡 建议补:业务流程图、页面线框图
④ 风险初筛     ⚠️ 踩中「资金业务透镜」:支付、金额
⑤ 增量对照     ✅ 无重复

📊 总结:骨架 ⚠️ · 质量 ⚠️ · 图 2 张 · 风险 ⚠️
```

照着补完再检,直到看到 "🎉 通过"。

## 第 5 步:交接给开发

**怎么做**:流水线跑完,把 `04-交付/` **整个文件夹复制**给开发同学。

**在哪做**:文件管理器(访达 / 资源管理器)。

**会有什么结果**:开发把它放进他们的 `010-requirements/` 目录,直接开工。你在产品侧的事情全部结束。

```
04-交付/ 里面有什么?
├── sources/     ← 定稿的需求快照(开发的输入)
├── converted/   ← 已转换好的素材文字
└── assets/      ← 原型图、流程图、参考截图(外链不丢)
```

## 常见问题

**Q:我不想记任何命令,行吗?**
行。全程对 AI 助手说话就行:

> "创建期次 Q4" → "跑流水线" → "把 REQ-001 标记为 评审通过" → "冻结期次 Q4"

**Q:跑一半断了怎么办?**
说"继续跑"(`--resume`),从断的地方接着来,不重头。

**Q:需求中途改了怎么办?**
说"REQ-001 有变更:预订增加改期功能"。冻结时会自动记录版本演进(v1.0 → v1.1),旧版本不丢。

**Q:各端需求文档格式想自己定,可以吗?**
可以。往 `00-素材/_templates/` 放模板文件(章节标题 + 一句话说明),有模板按你的来,没有就用系统默认。

**Q:方案拿不准,想对比几条路?**
说"预订这个功能做两个方案对比"。产出多案对比表,冻结时推荐方案进正文,其余留作备选附录。

## 一句话总结

建期次、投料、跑流水线——三件事;材料进去,定稿的需求出来,复制给开发就完事。
