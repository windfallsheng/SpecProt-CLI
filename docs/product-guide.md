# 产品操作指南（全流程版） · 需求定稿工坊

> 给产品同学看的完整手册。不用懂任何代码，每个节点都告诉你三件事：**怎么做、在哪做、会有什么结果**。
> 初次上手只看「第 0～3 步」就够跑完整条线；第 4～7 步是让需求更扎实的可选武器。

## 全流程地图

```
第 0 步 安装初始化（只做一次）──► 以后每次做需求：
第 1 步 建期次 ──► 第 2 步 投料 ──► 第 3 步 跑流水线 ──► 第 8 步 交接给开发
                                      ▲                  ▲
                                      │  第 4 步 体检    │
                                      │  第 5 步 原型图表 │── 可选，随时做
                                      │  第 6 步 设计系统 │
                                      │  第 7 步 正典库   │
```

## 第 0 步：安装与初始化（只做一次）

**怎么做**：安装工具 + 初始化，各一句话：

```bash
npm install -g spec-prot   # 安装
specprot init              # 在项目里初始化
```

（也可以直接对 AI 助手说：「安装 spec-prot 并初始化这个项目」。）

**在哪做**：终端，或 AI 编程工具的对话框。

**会有什么结果**：
- 项目里出现一个 `.speccore/GLOBAL/` 全局需求层——所有需求、术语、设计系统的「家底」都存这里，跨期次共用；
- AI 编程工具里多出一批斜杠命令（`/iteration-create`、`/run`、`/check`……），你发斜杠它就知道该怎么办。

**一句话**：初始化一次，之后 AI 助手全程听得懂人话。

## 第 1 步：建期次

**怎么做**：对你的 AI 助手说一句话：

> "创建期次 Q3，目标上线会议室预订"

（也可以敲：`specprot iteration create -n 期次-Q3 -p "web=网页端,backend=后端服务"`）

**端名小贴士**：各端目录叫什么，你自己定——
- 英文为佳（`web` / `admin-web` / `booking-service`），`=` 后面附中文说明，一眼就知道是哪端；
- 和开发那边（SpecCore）名字对不上也没关系，建期次时加 `-m "web=admin-web"` 建一张对照表，冻结交付时自动带上，开发拿到的永远是他们的名字。

**在哪做**：AI 编程工具的对话框，或终端。

**会有什么结果**：一个叫 `期次-Q3` 的文件夹，里面什么都准备好了：

```
期次-Q3/
├── 00-素材/          ← 你投料的地方（重点！）
│   ├── web/          ← 网页端素材
│   ├── backend/      ← 后端素材
│   ├── shared/       ← 两边都有关的
│   └── _templates/   ← 自定义模板（可选）
├── web/              ← web 端需求文档的家
├── backend/          ← 后端需求文档的家
├── _shared/          ← 跨端共用的术语表、规则
└── 04-交付/          ← 最后交出去的东西（先不用管）
```

## 第 2 步：投料

**怎么做**：把材料**拖进文件夹**——讨论记录、会议截图、Word/PDF/Excel、录音，统统可以：

```
期次-Q3/00-素材/
├── web/      ← 前端相关的扔这里
├── backend/  ← 后端相关的扔这里
└── shared/   ← 两边都有关的（业务规则、字段定义）扔这里
```

**在哪做**：文件管理器（访达 / 资源管理器）。

**会有什么结果**：什么都不用管，流水线会自动把它们转成文字（`00-素材/converted/`）、给图片建索引、给录音加转写提示。

**进阶**：想自己定需求文档的章节格式？往 `00-素材/_templates/` 放模板文件（章节标题 + 一句话说明），有模板按你的来，没有就用系统默认。

## 第 3 步：跑流水线

**怎么做**：对 AI 助手说：

> "跑流水线，交互模式"

（也可以敲：`specprot run -i 期次-Q3 -m interactive`。想全程自动就说「自动模式」，中间不停、六大闸口仍会替你把关。）

**在哪做**：AI 编程工具的对话框。

**会有什么结果**：六段自动接力，每段产出都看得见：

| 段 | 干什么 | 产出 |
| :--- | :--- | :--- |
| ① 转换 | 素材变文字、图片建索引 | `00-素材/converted/` |
| ② 分析 | 写成**完整需求文档**（七段：背景/场景/功能/页面接口/字段/规则/验收） | `{端}/REQUIREMENT.md` |
| ③ 切分 | 拆成功能单元（预订、支付……） | `{端}/features/{单元}/` |
| ④ 深化 | 风险清单 + 待确认清单 | 单元目录里的 RISK.md、CLARIFY.md |
| ⑤ 收养 | 需求进入「正典库」成为正式版本 | `.speccore/GLOBAL/` |
| ⑥ 冻结 | 交付包成形 | `04-交付/` |

**中途会停下来问你六件事**（这是刻意设计，替你把关）：

1. 范围对不对？
2. 素材是不是空的？
3. 需求骨架填满没有？
4. 待确认的问题解决没有？
5. 风险裁决完没有？
6. 确认收养这些需求吗？

答完继续跑；答不上来的，说明需求还没想清楚——正好趁机想清楚。

**跑一半断了**：说「继续跑」（`--resume`），从断的地方接着来，不重头。

## 第 4 步：随时体检（可选但推荐）

**怎么做**：写完一段需求后，随时说：

> "检查一下：用户支付订单，金额从余额扣除"

**在哪做**：AI 编程工具的对话框。五个入口，按你手头的东西选：

| 入口 | 命令 | 什么时候用 |
| :--- | :--- | :--- |
| 一段话 | `specprot check -s "…"` | 需求还在脑子里，先验验成色 |
| 一个文件 | `specprot check -f 需求.md` | 有份文档想体检 |
| 整个期次 | `specprot check -i 期次-Q3` | 全线巡检，出汇总表 |
| 某个端 | `specprot check -i 期次-Q3 -p web` | 只看网页端 |
| 某个单元 | `specprot check -i 期次-Q3 -p web -u 预订` | 只看一个功能 |

**会有什么结果**：一份体检报告，直接告诉你缺什么：

```
🩺 需求体检报告
① 骨架完整性   ⚠️ 缺：页面/接口、业务规则、验收标准
② 质量六维     ⚠️ 口语化"大概" / 无验收标准
③ 图资产建议   💡 建议补：业务流程图、页面线框图
④ 风险初筛     ⚠️ 踩中「资金业务透镜」：支付、金额
⑤ 增量对照     ✅ 与历史需求无重复
```

照着补完再检，直到看到 "🎉 通过"。

## 第 5 步：原型与图表（可选，让需求看得见）

**怎么做**：
- 要**可点的 HTML 原型**，说「给 web 端生成原型」（`specprot prototype -i 期次-Q3 -p web`）；
- 要**流程图 / 线框图**，说「给预订单元画图」（`specprot assets -i 期次-Q3 -p web -f 预订`）。

**在哪做**：AI 编程工具的对话框。

**会有什么结果**：
- 原型：`{端}/assets/prototypes/` 里一份能在浏览器里点着玩的 HTML，照着需求文档生成；
- 图表：流程图、状态图、线框图按单元生成，还有个总览页一次看全。

**交给谁看**：评审会上投屏原型讲需求，比念文档直观十倍。

## 第 6 步：设计系统（可选，风格沉淀一次）

**怎么做**：想统一各期次的原型风格，说：

> "从 xxx 设计稿/线上页面提取设计系统"

（`specprot design -s 代码目录` 或 `-u 页面URL`，支持 antd / element / tailwind 等。）

**在哪做**：AI 编程工具的对话框，或终端。

**会有什么结果**：设计系统落进全局层 `.speccore/GLOBAL/DESIGN_SYSTEM.yaml` + 一份风格指南 HTML——**跨期次共用**：以后每期原型自动套用同一套色彩、字体、组件，产品线风格不散架。

## 第 7 步：需求正典库（进阶：变更、版本、历史参考）

**它是什么**：`.speccore/GLOBAL/` 是需求的「单一事实源」——每期收养进来的需求都升格为正典（REQ-001、REQ-002……带版本号 v1.0），永不丢失。

**日常操作**（全部可以说人话）：

| 想干什么 | 说一句 | 命令 |
| :--- | :--- | :--- |
| 全局新建需求 | "新建需求：会员体系" | `specprot req new -n 会员体系 -d …` |
| 查看需求 | "REQ-001 是什么" | `specprot req show REQ-001` |
| 关联到期次 | "把 REQ-001 关联到 Q3" | `specprot req link --req REQ-001 -i 期次-Q3` |
| 更新状态 | "REQ-001 标记为 评审通过" | `specprot req status …` |
| 声明变更 | "REQ-001 有变更：预订增加改期" | `specprot req change REQ-001 -d …` |
| 收养单元 | 流水线第 ⑤ 段自动做 | `specprot req adopt` |

**变更怎么流转**：变更声明后，冻结时自动版本演进（v1.0 → v1.1），旧版本不丢，谁改了什么有据可查。

**AI 会参考历史吗**：会。跑「分析 / 切分」时，工具自动把**同端历史需求摘要**（最多 5 条）、期次共享的术语表和规则、设计系统一起塞给 AI——新需求与历史重复或冲突时，AI 会标「待确认」而不是擅自合并。你沉淀越多，AI 写得越像你们团队的手笔。

## 第 8 步：交接给开发

**怎么做**：流水线跑完，把 `04-交付/` **整个文件夹复制**给开发同学。

**在哪做**：文件管理器（访达 / 资源管理器）。

**会有什么结果**：开发把它放进他们的 `010-requirements/` 目录直接开工；`PLATFORM_MAP.yaml` 对照表确保两端名字无缝对上。你在产品侧的事情全部结束。

```
04-交付/ 里面有什么？
├── sources/          ← 定稿的需求快照（开发的输入）
├── converted/        ← 已转换好的素材文字
├── assets/           ← 原型图、流程图、参考截图（外链不丢）
└── PLATFORM_MAP.yaml ← 端名对照表（你起的名字 → 开发的名字）
```

### 只交部分端（导出）

- **只冻结某些端**：`specprot iteration freeze -n 期次名 -p web,booking-service` —— 快照、资产、端名对照表都只留这些端。不写 `-p` 就是全部端。

### 转成 Word / PDF（独立步骤，先导出后转换）

把上面导出的定稿快照转成别的格式，给业务评审、存档、盖章用：

```bash
specprot export -i 期次名 -f docx,html     # 已导出的全部端 → Word + HTML
specprot export -i 期次名 -p web -f pdf    # 只把 web 端的转成 PDF
```

产物在 `04-交付/exports/{格式}/{端}/`。**先 freeze 导出、再 export 转换，两步分开**；还没导出时 export 会提示你先去冻结。PDF 需要 LibreOffice（`brew install --cask libreoffice`），没装会提示跳过。

## 常用命令速查

| 动作 | 命令 |
| :--- | :--- |
| 初始化 | `specprot init` |
| 建期次 | `specprot iteration create -n 期次名 -p "web=网页端"` |
| 跑流水线 | `specprot run -i 期次名 -m interactive` |
| 体检 | `specprot check -s "一段需求"` |
| 原型 | `specprot prototype -i 期次名 -p 端名` |
| 图表 | `specprot assets -i 期次名 -p 端名 -f 单元名` |
| 方案对比 | `specprot schemes -i 期次名 -p 端名 -f 单元名` |
| 设计系统 | `specprot design -u 页面URL` |
| 需求管理 | `specprot req new / change / link / status …` |
| 冻结交付 | `specprot iteration freeze -n 期次名`（`-p 端1,端2` 只交部分端） |
| 转换格式 | `specprot export -i 期次名 -f docx,html`（`-p` 按端筛选） |

## 常见问题

**Q：我不想记任何命令，行吗？**
行。全程对 AI 助手说话就行：

> "创建期次 Q4" → "跑流水线" → "把 REQ-001 标记为 评审通过" → "冻结期次 Q4"

**Q：跑一半断了怎么办？**
说「继续跑」（`--resume`），从断的地方接着来，不重头。

**Q：需求中途改了怎么办？**
说「REQ-001 有变更：预订增加改期功能」。冻结时会自动记录版本演进（v1.0 → v1.1），旧版本不丢。

**Q：各端需求文档格式想自己定，可以吗？**
可以。往 `00-素材/_templates/` 放模板文件（章节标题 + 一句话说明），有模板按你的来，没有就用系统默认。

**Q：方案拿不准，想对比几条路？**
说「预订这个功能做两个方案对比」。产出多案对比表，冻结时推荐方案进正文，其余留作备选附录。

**Q：端目录名怎么定？和开发那边必须一致吗？**
英文为佳，`=` 后附中文标签；不必一致——建期次时 `-m` 建对照表，冻结自动随交付走。

**Q：AI 写需求会参考以前的历史需求吗？**
会。分析/切分时自动注入同端历史需求摘要 + 术语表 + 规则 + 设计系统，重复冲突会标「待确认」。

**Q：设计系统存在哪？换期次还要重新弄吗？**
存在全局层 `.speccore/GLOBAL/DESIGN_SYSTEM.yaml`，跨期次共用，弄一次全线受益。

**Q：初始化做过了，换项目要重做吗？**
要。`specprot init` 是按项目初始化的，每个新项目跑一次即可。

## 一句话总结

装一次、初始化一次；之后每期就是三件事——建期次、投料、跑流水线；材料进去，定稿的需求出来，复制给开发就完事。
