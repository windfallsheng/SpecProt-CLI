# SpecProt 概述 · 需求定稿工坊

SpecProt 是 SpecCore 生态的**第一道闸**——产品需求在这里定稿,然后以整目录镜像交接给 SpecCore 进入规格开发。

```
SpecProt(需求定稿) → SpecCore(规格开发) → SpecTest(测试验证)
     freeze              unitize              gate
```

## 解决什么问题

产品需求的原始形态是散乱的:讨论记录、会议截图、Word/PDF 文档、随手写的一段话。它们的问题不是"没有信息",而是**没有形状**——开发端无法直接消费。

SpecProt 把散乱素材锤炼成有形状的产出:

| 素材(输入) | 锤炼产物(输出) |
| :--- | :--- |
| 讨论记录 / 截图 / 文档 | `{端}/REQUIREMENT.md` 七段完整需求文档 |
| 端级需求文档 | `features/{单元}/` 可独立交付的功能单元 |
| 功能单元 | OUTLINE 结构契约 + 风险裁决评审包 |
| 需求内容 | Mermaid 图源 + 原型 HTML + 资产注册表 |
| 冻结期次 | `04-交付/` 镜像 → 整目录复制进 SpecCore |

## 设计哲学 — 三分分工

| 角色 | 管什么 | 怎么管 |
| :--- | :--- | :--- |
| **CLI** | 确定性 | 骨架预建、结构校验、闸口判定、版本演进 |
| **AI** | 语义 | 成文、切分、深化、图资产(经 `[SPECPROT_PROMPT]` 接力) |
| **人** | 闸口 | 范围确认、待确认裁决、风险裁决、收养确认 |

CLI 不猜语义,AI 不碰确定性,人只把六道闸。三者各守其位,流水线才能既稳又快。

## 核心能力全景

1. **六段流水线** — convert → analyze → slice → deepen → adopt → freeze,双模式(全自动/人机交互)+ 断点续跑
2. **自然语言入口** — `ask` 执行引擎,说人话就办,参数缺失点名追问
3. **五维体检** — `check` 随时体检:骨架/质量/图建议/风险初筛/增量对照,五级入口
4. **模板优先** — 产品按端投模板,有模板用模板,无模板系统兜底
5. **方案分叉** — `schemes` 多案对比,冻结时推荐进快照正文,其余进备选附录
6. **风险透镜** — 七个业内标准透镜(资金/金融合规/隐私/无障碍/内容/并发/状态机)
7. **交付镜像** — `04-交付/` 与 SpecCore `010-requirements/` 同构,复制即交接
