# prot-once — 单会话端到端定稿

## 使用说明（用户仅询问「怎么用/使用说明/使用步骤/能干什么」时，输出本指南，不启动流程）

**它是什么**：SpecProt 的单会话端到端定稿技能——把「需求 → 切分 → 深化 → 裁决 → 冻结交付」整条产品链在这一次对话里跑完，全程由 AI 按剧本编排 specprot 命令，AI 接力段（分析/切分/深化）在同会话内直接填充产物。

**怎么触发**：直接对 AI 说，例如：
- 「prot once，把这个 PRD 定稿交付：/path/to/PRD.docx」
- 「一次跑完：做一个会议室预订功能」（一句话需求也可以）
- 「小步快跑：把期次-Q3 里 web 端的素材加工到冻结」

**三种入口**：
1. **一句话需求**——AI 先整理成 PRD 级需求文档投进素材区，再开工
2. **一个 PRD 文档地址**——.md 直接投料；.docx/.pdf 投料后走 convert 转换
3. **已投料的期次**——素材已在 `00-素材/`，直接开工（建议 ≤3 个功能单元，多了建议走流水线）

**两种执行模式**：
- **人机交互（默认）**：每个节点停下等你确认（范围 → 转换 → 分析 → 切分 → 深化 → 裁决 → 冻结），适合要盯过程的场景
- **全自动**：说「全自动/别停下」即可，节点间不等待；只有四个安全点会停下：范围确认、风险裁决（产品拍板，AI 不代劳）、CLARIFY 待确认未清、冻结门禁失败

**七步流程**：① 入口识别与范围确认 → ② 素材转换 → ③ 端级分析 → ④ 功能切分 → ⑤ 单元深化 → ⑥ 风险裁决 → ⑦ 收养正典 + 冻结交付

**跑完后可继续**：`specprot export -i 期次名 -f docx,html` 转成 Word/HTML 交付（可选，按需）。

**哪一步不满意可回退重跑**：
- 分析不好 → 重跑 analyze 覆盖端级需求文档
- 切分不理想 → 重跑 slice 重建功能单元
- 深化不满意 → 重跑 deepen（outline / review 分阶段）
- 裁决打错 → resolve 重新列出重打（裁决后编号重排，注意按新编号操作）

**适用边界**：少量功能单元（≤3）的快速定稿闭环；不适合大范围多单元（走 `specprot run` 流水线）。


## 定位

把「入口 → 转换 → 分析 → 切分 → 深化 → 裁决 → 冻结交付」七步装进一次会话，一步定稿。
底层全部复用 specprot 现有命令，本 skill 只做编排与交互节点。与 spec-once（开发侧）
对称：spec-once 把需求变成可运行代码，prot-once 把需求变成可交接的定稿交付镜像
（`04-交付/`，直接投给 SpecCore 的 `010-requirements/sources/` 开工）。

## 执行模式（入口先识别）

**默认：人机交互模式**——每个节点停下等用户确认（范围 → 转换 → 分析 → 切分 → 深化 → 裁决 → 冻结）。

**全自动模式**——用户说「全自动 / 自动跑 / 一路跑完 / 别停下 / --auto」时启用：
- 节点间不等待确认，自动推进：转换完直接 analyze → 分析完直接 slice → 切分完直接 deepen
- **仍必须停下的四个安全点**：① 范围确认（起点，必须知道范围）② 风险裁决（产品决策权，AI 不得代拍板）③ CLARIFY 待确认未清（切片前闸口）④ 冻结门禁失败（待裁决/未决拦截）
- 用户中途说「停下/改为手动」→ 立即切回交互模式，后续节点恢复确认

## 流程（逐步执行，禁止跳步；交互模式每节点停下，全自动模式仅四个安全点停下）

### Step 0 入口识别与范围确认

先识别用户给了什么，按入口执行预处理，再统一做范围确认：

**入口 A：一句话需求**
- 把口语化需求整理成 PRD 级需求文档，写入期次素材区 `{期次}/00-素材/{端}/`（按端归类的约定见入口 C 的投料规则）
- 端名不确定时向用户确认（端名是产品自定的，如 web / admin-web / booking-service）

**入口 B：一个 PRD 文档地址**（.md / .docx / .pdf，多个可批量）
- `.md` → 直接投料：复制到 `{期次}/00-素材/{端}/`
- `.docx/.pdf` → 复制到素材区后由 Step 1 的 convert 转换
- 投料按端归类：端专属素材放 `00-素材/{端}/`，跨端通用内容放 `00-素材/shared/`

**入口 C：已投料的期次**
- 素材已在 `00-素材/`，无需预处理，直接进入下方「范围确认」

**期次准备（入口 A/B 必做，入口 C 探测）**
1. `specprot iteration list --detail` 查看期次是否存在；不存在则 `specprot iteration create -n 期次名 -p 端1,端2`（-p 声明本次覆盖的端列表）
2. 已存在则确认期次内的端与本次范围是否一致，缺端时先向用户确认是否扩建

**范围确认（三入口统一汇合点）**
1. `specprot iteration show -n 期次名` 查看端列表、素材、已有单元
2. 向用户确认本次范围：做哪几个端、预期产出几个功能单元
3. 边界提醒：单会话建议 ≤3 个功能单元；范围过大时警告「上下文可能超载，建议分批或改用流水线 specprot run」，用户坚持再继续
4. 对每个端检查 `{期次}/{端}/REQUIREMENT.md` 与 `{端}/features/` 是否已有产物——有则交互模式问用户「跳过 / 重做」；全自动模式默认跳过（用户明确要重做时走步骤回退重跑协议）

### Step 1 素材转换
1. 执行 `specprot convert -i 期次名`（-p 只转指定端；转换 docx/pdf/xlsx → md 一字不差，图片建索引）
2. 转换是确定性操作，CLI 自行完成，输出 `[SPECPROT_STEP_DONE]` 后继续
3. 转换产物落在 `00-素材/converted/{端}/`；闸口「素材为空」拦截时报错即停，向用户报告「素材区无料」，收料后重试
4. **音视频接力**：若存在 `00-素材/converted/_pending-ai.md`（convert 按 .specprot.yml 的 ai 模式生成）：
   - 宿主 AI 按清单处理协议逐个处理：读原文件（多模态）→ 转写 → 四板斧提炼（去噪/分段/结论先行/溯源）
   - 提炼稿写入 `00-素材/converted/{端}/_refined/{原名}.md`（文件头标注提炼自，文末附「待确认」）
   - 视频拆两路：音轨转写 + 每 30 秒抽关键帧存 `00-素材/{端}/frames/`
   - 全部处理完删除 `_pending-ai.md`；交互模式向用户汇报提炼摘要并**停下等确认**；全自动模式直接进 Step 2
5. 无待处理清单则交互模式**停下等确认**，全自动直接进 Step 2

### Step 2 端级分析（AI 接力）
1. 对范围内每个端执行 `specprot analyze -i 期次名 -p 端名`
2. stdout 出现 `[SPECPROT_PROMPT]` → 将 Prompt 内容作为你的工作指令执行（不要改写、不要略过），**产物直接覆盖写入迭代目录**：
   - `{期次}/{端}/REQUIREMENT.md` — 端级完整需求文档
   - `{期次}/{端}/CLARIFY.md` — 待确认清单
3. Prompt 中「提炼稿」节是优先依据，原文节仅作回溯核对；两者冲突以提炼稿为准，疑点记入 CLARIFY
4. 分析中发现需求模糊点 → **向用户提问澄清**，不要自行脑补
5. 完成后汇报分析产出摘要（端、文档、关键结论），交互模式**停下等确认**；全自动模式直接进 Step 3

### Step 3 功能切分（AI 接力）
1. 对范围内每个端执行 `specprot slice -i 期次名 -p 端名`
2. 拿到 `[SPECPROT_PROMPT]` 后按 Prompt 切分，产物直接写入：
   - `{期次}/{端}/features/{单元名}/REQUIREMENT.md` — 每个功能单元一份
   - `{期次}/{端}/features/INDEX.md` — 功能单元索引
   - 每个单元文档必须含「素材溯源」段（端级需求 + 原始素材文件名）
3. 切分前若该端 CLARIFY.md 仍有未决项 → 先向用户确认清空（闸口四「待确认未清」的语义），不要带病切分
4. 汇报切分出的功能单元清单与依赖关系，交互模式**停下问用户**「切分是否合理？需要调整吗？」；全自动模式直接进 Step 4

### Step 4 单元深化（AI 接力，两个子阶段）
对范围内每个功能单元执行（单元多时可逐单元推进）：
1. **结构契约**：`specprot deepen -i 期次名 -p 端名 -f 单元名 --phase outline`
   - 拿到 `[SPECPROT_PROMPT]` 后按 Prompt 写入 `{单元}/OUTLINE.md`（章节树结构契约）
   - OUTLINE 四段必须齐全（缺段时 review 阶段会被校验拦下）
2. **评审包**：`specprot deepen -i 期次名 -p 端名 -f 单元名 --phase review`
   - 按 Prompt 覆盖深化 `{单元}/REQUIREMENT.md`（按 OUTLINE 章节树逐章）
   - 写风险裁决表 `{单元}/RISK.md`（待裁决项留「待裁决」标记，**不要 AI 代裁决**）
   - 追加待确认到 `{单元}/CLARIFY.md`（增量，勿删旧行）
   - REBOUND 回流：确认的新术语/跨单元规则追加到 `{期次}/_shared/GLOSSARY.md` 与 RULES.md
3. 汇报每个单元的深化摘要（结构、风险条目数、待确认数），交互模式**停下等确认**；全自动模式直接进 Step 5

### Step 5 风险裁决（产品决策权，全自动模式也停下）
1. 对每个有「待裁决/未决」的单元执行 `specprot resolve -i 期次名 -p 端名 -f 单元名` 列出统一编号清单
2. 逐条向用户展示风险/澄清项，**由用户拍板**（AI 只解释背景与建议，不代替裁决）
3. 按用户决定执行 `specprot resolve -i 期次名 -p 端名 -f 单元名 --item 序号 --decision accept|reject --note 备注`（CLARIFY 未决项用 accept/reject 裁决后同样清零）
4. 注意：裁决后编号会重排，CLI 会打印剩余清单——连续裁决时按最新清单的编号操作
5. 全部清零后汇报「门禁已清零，可冻结」，交互模式**停下等确认**；全自动模式直接进 Step 6

### Step 6 收养正典 + 冻结交付
1. 对范围内每个功能单元执行 `specprot adopt -i 期次名 -p 端名 -f 单元名`（收养进正典库 GLOBAL/PROJECTS，幂等——重复收养返回既有 REQ）
2. 全部收养后执行 `specprot iteration freeze -n 期次名`
   - 冻结时变更需求自动回流版本演进（vX.Y → vX.(Y+1)）
   - 门禁扫描 RISK「待裁决」与 CLARIFY「未决」——仍有未裁决项则被拦截，回到 Step 5 清零后重试
3. 冻结成功 → 汇报交付镜像清单：`04-交付/sources/`（定稿快照）、`converted/`（素材转换产物）、`assets/`（原型/图源）、`PLATFORM_MAP.yaml`（端名映射桥）
4. 交付镜像就是给 SpecCore 的输入：复制 `04-交付/sources/*.md` 到 SpecCore 迭代的 `010-requirements/sources/`，产品侧定稿流程结束

### Step 7 可选收尾：转格式交付（不自动执行）
- 提示用户可选操作：`specprot export -i 期次名 -f docx,html`（先 freeze 后转换，两步独立），产物在 `{期次}/exports/{格式}/{端}/`
- 用户需要 PDF 时提醒：本机需装 LibreOffice（`brew install --cask libreoffice`），未装则优雅跳过 pdf 只出其余格式

## 步骤回退重跑协议

用户对某一步产出不满意时，按以下路径回退（前序步骤产物无需重做，上下文不会错位）：

| 场景 | 回退命令 | 说明 |
| :--- | :--- | :--- |
| **分析内容不好** | `specprot analyze -i 期次名 -p 端名` 重拿 Prompt，重新覆盖写 `{端}/REQUIREMENT.md` 与 CLARIFY.md | 只影响该端，其它端不动 |
| **切分不理想** | `specprot slice -i 期次名 -p 端名` 重新切分，重建 `features/` 索引与单元文档 | 重切会覆盖同名单元目录，先向用户确认 |
| **结构契约不对** | `specprot deepen -i 期次名 -p 端名 -f 单元名 --phase outline` 重生成 OUTLINE.md | 缺段被校验拦下时也可补齐后重跑 review |
| **评审包不满意** | `specprot deepen -i 期次名 -p 端名 -f 单元名 --phase review` 重出 RISK/CLARIFY 增量 | CLARIFY 是增量追加，重跑前确认旧行处理 |
| **裁决打错对象** | `specprot resolve -i 期次名 -p 端名 -f 单元名` 重列清单，按新编号重打 | 裁决后编号重排，必须看最新清单 |

重跑后从该步继续向下推进。

## 输出标记处理

- `[SPECPROT_PROMPT]` / `[SPECPROT_PROMPT_END]` → 将两者之间的 Prompt 内容作为你的工作指令执行（不要改写、不要略过），产物按 Prompt 指定路径直接写入迭代目录
- `[SPECPROT_STEP_DONE]` → 告知用户本段完成；**prot-once 单会话模式下不必开新会话**，宿主 AI 直接执行下一步命令继续
- `[SPECPROT_NEXT_STEP]` → 提示 `specprot run --resume` 的续跑方式；但 once 模式下由宿主 AI 直接执行下一段命令（如 analyze 后直接 slice），不交给 run
- `[SPECPROT_NEEDS_INFO]` → 用交互式提问向用户收集缺失参数，收齐后重新执行
- 其他 `[SPECPROT_*]` 标记 → 按 specprot ask 引擎的语义原样转达

## 铁律

- **默认交互模式：每个节点停下等用户确认**（范围 → 转换 → 分析 → 切分 → 深化 → 裁决 → 冻结）；全自动模式下仅四个安全点停下（范围确认 / 风险裁决 / CLARIFY 未清 / 冻结门禁失败）
- **风险裁决是产品决策权，AI 不得代拍板**——RISK/CLARIFY 里的「待裁决/未决」必须由用户逐条拍板，全自动模式也不例外
- AI 接力段的产物按 Prompt 指定路径直接写入迭代目录（SpecProt 的迭代层是加工车间，与 SpecCore 禁止 AI 写 Spec 文件的规则不同）；**但正典库 GLOBAL/PROJECTS/ 只能经 adopt/freeze 等 CLI 命令写入，禁止直接改**
- 失败时向用户报告根因与 .issues 提示，不要静默跳过；冻结门禁不通过不得宣布流程完成
- 步骤回退重跑一律走「步骤回退重跑协议」中的命令，禁止手改目录或文档绕过 CLI
- 单会话上下文不够时（prompt 超预算报错），停下建议用户改用流水线 `specprot run` 分步执行
